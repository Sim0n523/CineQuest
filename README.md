# CineQuest

A gamified movie-tracking app built with Flutter. This package is the
**Phase 1** scaffold from the CineQuest blueprint: Authentication,
Navigation, Firebase, TMDB integration, Movie Details, and Search.

## What's in here

This is the `lib/` folder, `pubspec.yaml`, and a few config files — not a
complete Flutter project (no `android/`/`ios/` folders). That's intentional:
those folders are generated by the Flutter tool itself and are specific to
the Flutter SDK version on your machine, so you'll create them locally in
step 1 below.

## Setup

### 1. Create the Flutter project shell

```
flutter create cinequest
cd cinequest
```

This generates `android/`, `ios/`, `web/`, etc. — the native scaffolding.

### 2. Drop in this package

Replace the generated `lib/` folder and `pubspec.yaml` with the ones from
this zip. Also copy `analysis_options.yaml`, `.gitignore`, and
`firestore.rules` into the project root.

### 3. Install packages

```
flutter pub get
```

### 4. Firebase

1. Create a project at https://console.firebase.google.com
2. Authentication → Sign-in method → enable **Email/Password**
3. Firestore Database → Create database (production mode is fine — the
   rules below lock it down)
4. Install the Firebase and FlutterFire CLIs, then run from the project root:
   ```
   npm install -g firebase-tools
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
   This walks you through selecting your Firebase project and platforms,
   registers the Android/iOS apps, wires up the native config
   automatically, and generates `lib/firebase_options.dart`.
5. In `lib/main.dart`, uncomment the `firebase_options.dart` import and
   pass `options: DefaultFirebaseOptions.currentPlatform` to
   `Firebase.initializeApp(...)`.
6. Paste `firestore.rules` into Firestore → Rules in the console (or
   `firebase deploy --only firestore:rules` if you've also run
   `firebase init`).

### 5. TMDB API key

1. Create a free account at https://www.themoviedb.org and request an API
   key under Settings → API
2. Paste it into `lib/utils/app_constants.dart` → `tmdbApiKey`

### 6. Run it

```
flutter run
```

## Architecture

Follows the blueprint's folder structure (section 6) exactly:

- `core/models` — plain Dart data classes (`UserModel`, `MovieModel`)
- `core/services` — the only layer allowed to talk to Firebase/TMDB
  directly (`AuthService`, `TMDBService`)
- `core/repositories` — sits between services and providers
  (`MovieRepository`); this is where caching gets added later
- `core/providers` — `ChangeNotifier`s screens listen to (`AuthProvider`,
  `MovieProvider`)
- `screens` / `widgets` — UI only, no business logic
- `themes` — the blueprint's exact color palette and Inter typography
- `utils` — constants, XP/level config, route names

## What's deliberately stubbed

- **Quests, Leaderboard tabs** — placeholder screens; these come alive in
  Phase 4, once XP is actually being earned.
- **Profile stats** — the fields exist on `UserModel` and render zeroed
  out; `ProgressionService` (Phase 3) is what will start incrementing them.
- **"Log This Movie" button** — shows a snackbar for now. Movie logging is
  Phase 2.

## A small heads-up on scope

The blueprint puts XP/Levels in Phase 3, but the Firestore user document
needs `xp`/`level`/stat fields from the very first user who registers — so
`UserModel` and a config-driven `LevelConfig` (in `utils/xp_config.dart`,
storing thresholds as a list per section 13's instruction) are included
now, unused by any reward flow yet. Flagging this since it's a small
deviation from strict phase ordering, per the blueprint's own instructions
to call out conflicts rather than silently change direction.

## Known versioning caveat

This sandbox can't run the Flutter toolchain, so this code is carefully
written and reviewed but not compiler-verified. Package versions in
`pubspec.yaml` were checked against pub.dev at the time of writing
(firebase_core 4.9.0, firebase_auth 6.5.3, cloud_firestore 6.1.2 — note
these are newer major versions than a lot of older Firebase+Flutter
tutorials assume). If `flutter pub get` or `flutter analyze` flags
anything, paste me the error and I'll fix it fast.
